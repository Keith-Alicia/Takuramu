# MVP範囲

## MVP定義

### 目的
「独り言（音声）とURL・写真だけで、共有したくなるクオリティの飲食店紹介記事が生成できるか」というコア体験を検証する。

### 対象ユーザー
自分自身（飲食店をよく知っており、友人から頻繁にお店を聞かれる人）および、その友人（初期の共有先）。

### 成功の定義
自分が日常的にLINEで友人に飲食店を共有する際に、以前の「URL＋手打ち長文」の代わりに、このアプリで生成したURLを自発的に使うようになること。

## スコープ

### MVP に含める ✅
| 機能 | 理由 |
|------|------|
| ポートフォリオ（リスト）作成 | お店をグループ化して共有するために必須 |
| お店データの追加（URL, 写真, 音声） | コアとなる入力体験のため必須 |
| AIによる記事自動生成 | 最も重要なコアバリューであるため必須 |
| Pinterest/Instagram風の閲覧UI | 受け取る側の感動体験を作るために必須 |
| URLによる外部共有 | LINE等で友人に教えるために必須 |

### MVP に含めない ❌
| 機能 | 理由 | 対応時期 |
|------|------|----------|
| URLからの店舗情報自動スクレイピング | 最初は手動入力やURLリンクのみで代替可能 | Phase 2 |
| 生成された記事の後からの編集機能 | まずは「一発生成」のクオリティ検証を優先 | Phase 2 |
| 閲覧制限（公開/非公開の詳細制御） | 初期はURLを知っている人だけが見られれば十分 | Phase 2 |
| 複数人での共同編集 | 個人利用からスタートするため不要 | 将来検討 |
| 位置情報（GPS）サジェスト | コア価値の検証には直結しないため | 将来検討 |

## タイムライン（目安）

| フェーズ | 期間 | 内容 |
|----------|------|------|
| MVP | 約1〜2週間 | コアとなる入力・生成・共有体験の構築（個人で使えるレベル） |
| Phase 2 | 未定 | 自動スクレイピング、編集機能、UIのブラッシュアップ |
| Phase 3 | 未定 | バイラルループ強化（受信者からの新規登録フローの最適化） |

## 制約事項
- AI（LLM）APIおよび音声認識APIの利用コスト
- 個人プロジェクトとしての開発リソース

## リスクと対策
| リスク | 対策 |
|--------|------|
| AI生成文章のクオリティが低く、手直しが必要になる | プロンプトエンジニアリングの調整に時間をかける。トーン＆マナーの指定を細かく行う。 |
| 音声入力のハードルが高い | UI上で「ただ話すだけでOK」と心理的ハードルを下げる工夫をする。 |
