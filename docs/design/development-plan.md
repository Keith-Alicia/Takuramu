# 開発計画書 (Development Plan)

## 1. 開発方針とアプローチ

本プロジェクトは個人開発であり、新規性の高いコア機能（音声入力からAIが洗練された記事を自動生成し、バイラルを生む体験）の仮説検証を最優先とします。
そのため、**アジャイル（イテレーティブ）なMVPアプローチ**を採用し、約1〜2週間の短期間で実際に動くプロダクトを構築・リリースします。

## 2. 開発ロードマップ

### Phase 1: MVP（Minimum Viable Product）構築【ターゲット：1〜2週間】
**目標**: コアバリューである「手軽な入力」と「エモーショナルな読後感の共有」が機能し、自身で実際に利用して友人にURLを送信できる状態にする。

- 認証・DBなどのインフラセットアップ（Supabase, Clerk）
- ポートフォリオ（リスト）の作成と管理機能
- お店データ（食べログURL、写真最大3枚、音声）の入力・保存機能
- Whisper + GPTによる記事自動生成AI連携（プロンプトチューニング含む）
- 洗練されたパブリック閲覧画面（一覧・詳細）のUI実装
- アプリ内での「URLコピー」によるシンプルな共有機能

### Phase 2: コア体験のブラッシュアップ（MVPリリース後）
**目標**: 自身や初期テストユーザーからのフィードバックを基に、ユーザビリティの向上とリスクへの対応を行う。

- 生成されたテキストの手動編集機能（一発生成で満足いかなかった場合のフォロー）
- 食べログURLからの簡易的なスクレイピング（店名・住所程度の自動補完によるUI向上）
- パブリック閲覧時の細かいアクセス制御（公開/非公開トグル）

### Phase 3: グロース・バイラル強化（将来構想）
**目標**: プラットフォームとしての拡大を目指す。

- 受信者（未登録ユーザー）から新規登録への導線のABテスト・最適化
- GPSを用いた近隣店舗のサジェスト機能
- 複数人でのポートフォリオ共同編集機能

## 4. リスク管理

開発・運用において想定される主要リスクと、その対応策を事前に定義します。

| リスク | 影響度 | 対策方針 |
| :--- | :--- | :--- |
| **AIの生成テキスト品質が安定しない** | 高 | 開発の初期段階でプロンプトのチューニング（Few-shotプロンプティングなど）に時間を割く。MVPでは最悪手動で修正可能な構成にフェーズ2で移行することも見据える。 |
| **音声入力の心理的ハードルが高い** | 高 | UI上で「ただ話すだけでOK」「あー、えーと等が含まれてもAIが綺麗にします」といったガイドを明示し、心理的障壁を下げる工夫をする。 |
| **他者の写真（著作物）の無断共有リスク** | 高 | 情報元として食べログURLをリンクとして併記し出処を明確にする。利用規約でユーザー自身が撮影した写真の使用を求める設計とする。 |
| **AI API（Whisper, GPT）のコスト高騰** | 中 | 個人開発の予算制約上、MVP段階では高価なモデルを避け、GPT-4o miniなどの安価なモデルを使用する。 |
